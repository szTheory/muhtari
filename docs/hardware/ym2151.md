# YM2151 on the XM

Muhtari supports one declared digital profile: an OPM/YM2151 inside the
existing XM cartridge topology. It is an emulator contract built from the
sources below. It does not claim measured XM wiring, physical clock accuracy,
analog gain, or retail-game compatibility.

## Selection and register access

The cartridge must be selected as XM and declare the YM2151 device. Unsupported
YM topologies continue to be rejected before installation. The chip's address
and data ports are `$0460` and `$0461`; reads from `$0461` return status and
reads from `$0460` return the existing open-bus value. Register access is
enabled when bit 7 of the exact whole-byte `$0470` XM control latch is set.
Clearing bit 7 disables register access without resetting the chip. The `$84`
value in the programming example is one enable value, not an equality test.
Existing control bits 3–6 and the `$0478`/`$047C` page registers keep their
current meanings. There are no `$0471`/`$0472` aliases or separate YM enable
latches.

Advance the chip by one YM clock for every two MARIA master ticks, independent
of CPU slow cycles and HALT. Keep the clock as an integer tick cadence rather
than reducing NTSC to a truncated integer frequency: NTSC is
315,000,000/88 Hz and PAL is 3,546,894 Hz. Timer IRQ reaches the existing bus
IRQ pipeline only when a valid A78 v4 header declares YM IRQ source bit 2.
Headerless, v3, and ignored or invalid v4 metadata do not imply a YM IRQ wire.

These are selected digital behaviors. The [profile evidence](../../.planning/research/ym2151-profile/EVIDENCE.md)
records the source conflict around `$0470`, the clock alternatives, and the
physical evidence limits.

## Busy and timer expectations

The Yamaha YM2151 Application Manual §2.1.1 says the write-busy status remains
high for 68 `φM` periods after a data write. This is a documented duration, not
a range. The pinned ymfm OPM implementation requests `32 * clock_prescale()`
busy periods; its YM2151 prescale is 2, so the seed convention is 64 periods.
The production profile follows Yamaha's 68-period statement. Parity reports
test busy separately and compare timer/status flags and output independently;
the two busy durations are not treated as equivalent.

Application Manual §2.1.7 gives `64 * (1024 - A)` periods for Timer A and
`1024 * (256 - B)` for Timer B, with φM = 3.579545 MHz in its example. Timer
mode bits 2 and 3 enable the corresponding carry flag; reset bits 4 and 5
clear those latched flags. The internal IRQ follows the latched timer flags and
remains asserted if a carry-enable bit is later cleared. The manual describes
the external IRQ pin as active low on a timer carry. Its pin description also
states that the internal clock is half the φM input frequency. The
implementation schedules these integer φM periods on the Atari master-tick
lattice and keeps timer IRQ routing subject to qualified A78 v4 YM wiring.

The implementation merges YM output through each TIA event and then each
actual POKEY CLK2 half edge before POKEY can emit. Slow-cycle completion
consumes the remaining tick. Timer deadlines still bound held-cycle batches;
they cannot advance YM audio ahead of an earlier TIA/POKEY edge. The combined
stress test checks all twelve raw sources in chronological order in Release
as well as assertion-enabled sanitizer builds.

The C-only numeric test checks busy at 67, 68, and 69 `φM` periods. It checks
Timer A at its 64-period minimum and 65,536-period maximum, and Timer B at its
1,024-period minimum and 262,144-period maximum. Each timer is asserted absent
just before carry, present on and after carry, and cleared only by its reset
bit. It also checks the mode-write/carry edge ordering against the pinned
implementation; the manual does not specify a physical XM bus arbitration
rule for that same-edge case.

## Mono output and numeric bounds

The public API continues to emit signed mono PCM. The OPM's left and right
outputs are first quantized by the YM3012 model into signed 16-bit samples.
For an installed YM topology, let `B` be the existing TIA/POKEY normalized
level, `L` and `R` the signed chip outputs, and `trunc0` division toward zero:

```text
A     = trunc0((L + R) / 2)
Y     = trunc0((A * 4590) / 32768)
level = floor(B / 2) + Y
```

This deterministic attenuation is not a physical XM resistor or loudness
calibration. It applies whenever YM is installed, even while its register port
is disabled. If YM is absent, the original mixer path and output remain
unchanged.

The DAC bounds are `L,R ∈ [-32768,32767]`, so `A ∈ [-32768,32767]` and
`A * 4590 ∈ [-150405120,150400530]`, all within signed 32-bit arithmetic.
For `B ∈ [0,18360]`, `floor(B/2) ∈ [0,9180]` and `Y ∈ [-4590,4589]`; hence
the complete mixed level is `[-4590,13769]`, with width 18,359. That width
stays below the existing 18,360 input bound. The prepared mixer derivation
also bounds both NTSC and PAL reconstruction, ring cells, integrator,
DC-blocker and PCM headroom within the existing limits. See
[the complete arithmetic derivation](../../.planning/research/ym2151-integration/MIXER-BOUND.md).

Private observation source 10 is the left output and source 11 is the right
output. Signed YM samples use a 16-bit two's-complement bit encoding. Decode
into a bounded signed 32-bit value before mixing; do not rely on
implementation-defined conversion from an out-of-range unsigned value to a
signed type. The runner keeps its existing 11-byte record shape, and records
for all older audio sources remain byte-for-byte unchanged.

## Power-on lifecycle

Power-on and accepted content replacement clear YM clocks, timer/busy state,
output words, LFO/noise phase, and register-derived caches to the same
deterministic baseline as a newly loaded chip. This is an emulator lifecycle
contract; reset does not preserve runtime noise-generator phase across a
power-cycle.

## State and consumer support

The complete YM snapshot uses native format 2 / behavior revision 7. It
captures clocks, timer/busy and IRQ state, registers, operators/envelopes,
feedback, noise/LFO, signed raw outputs and reconstruction history. One
canonical visitor validates the complete snapshot before mutation. CRC,
semantic, reset-relative clock/remainder chronology, identity, topology, short/trailing and future-version
refusals preserve the live machine and committed battery. Non-YM snapshots
retain their exact format-1/revision-6 identity, layout and bytes. API 8 and
ABI 1 are unchanged; global version reporting names the latest supported 8/3.
The genuine ten-case old/new matrix proves the named non-YM envelopes in both
directions. Old code refuses YM content and new snapshots safely; it does not
migrate them. A size error can precede an unsupported-version status.

The same owned image runs through the public C API, runner process, dynamically
loaded native libretro module, emitted Wasm and clean-extracted packages.
Libretro duplicates each mono sample into both channels. Batch, per-sample
fallback and absent-audio callbacks preserve chip progression. The runner uses
its existing probe, expansion, diagnostic, audio-hash and state options; no
sound device or new public output channel is required. An unsupported YM reload
is preflighted before libretro replaces the running session. Other malformed
reloads retain their documented release behavior.

## Reproducing the evidence

After the normal native workflow, generated cartridges live under
`build/ci/tests/ym2151/`; no generated media or state is committed.

```sh
ctest --test-dir build/ci --output-on-failure --no-tests=error -R '^ym[.]'
ctest --test-dir build/ci --output-on-failure --no-tests=error -R '^libretro[.](host[.]ym|observe[.]ym)'
cmake -DROOT=. -DSEED=build/v6-ym-seed -DWORK=build/v6-ym-oracle -P tests/audio/ym_oracle.cmake
cmake -DROOT=. -DOLD_SOURCE=.worktrees/ym-state-baseline -DOLD_BUILD=build/v6-state-baseline -DNEW_BUILD=build/ci -DWORK=build/v6-state-compat -P tests/core/state_compat.cmake
cmake -DROOT=. -DOLD_SOURCE=.worktrees/ym-state-baseline -DOLD_BUILD=build/v6-state-baseline -DNEW_BUILD=build/ci -DWORK=build/v6-state-compat -DMODE=controls -P tests/core/state_compat.cmake
sh scripts/emscripten.sh build/ci
```

The old source/build and exact seed object are independently prepared inputs,
verified by their source/header/library receipts. The compatibility command
builds only its two caller programs; it does not rebuild or modify the old core.
The portable command uses the existing pinned SDK, Node and CMake with network
disabled during build/execution. It refreshes native receipts and runs emitted
and extracted ZIP consumers, exact inventories and pass/fault controls.

`libretro.observe.ym` measures both named workloads in NTSC/PAL. Each case uses
12 warm-up frames and three complete restored 60-frame windows, including
callback copying and canonical frame/audio hashing. The portable report uses
the same work and records native and Node timings, source/fixture identities,
compiler/Node/platform, loader/Wasm sizes and digests. JSON stays under
`build/ci/tests/emscripten/ym*-measurement.json`; native receipts are alongside.
These observed-host costs have no speed threshold and predict no browser,
handheld or physical-audio result.

The ordinary cartridge keys one note and independently records busy, both timer
flags and IRQ handling. The stress cartridge runs all 32 operators across eight
channels with full feedback/carrier summing, fast noise/LFO, both shortest
running timers, both POKEYs and TIA, XM RAM/HSC gates and sustained register
writes. Its guest locks 7800 mapping before TIA writes and masks CPU IRQ service
during address/data traffic; the separate hostile test covers live IRQ entry,
return, JAM and maximum instruction overshoot. This is an executed adverse
workload, not proof that every legal program is faster.

The measured unloaded native instance requests 91,720 bytes versus 89,144 in
the genuine pre-YM build (2,576 extra). The optional private raw observer
requests 1,492,816 bytes separately, before load, versus 829,352 previously;
normal library/libretro use does not allocate it. These are allocator-requested
extents on the measured native target, not RSS. The YM struct is 2,568 bytes.
The diagnostic YM state is 179,330 bytes; unchanged non-YM envelopes keep their
old size. Tests require zero core allocation after load.

Work is finite: each output step evaluates at most eight channels and 32
operators; an output edge occurs every 128 MARIA ticks. Timer deadlines bound
held-bus catch-up and use overflow-safe distances. The existing 20,730-tick
instruction/interrupt overshoot allows at most 248,772 private carry records,
with 16-bit offsets. The public FIFO remains 1,103 samples, including the
existing 962-sample PAL frame and 141 future samples. Signed mixing stays inside
the original Q23/Q30 ring/integrator/DC bounds; endpoint and actual OPM tests
confirm the independent arithmetic. Functional bounds are separate from timing
measurements and do not impose a new performance or memory quota.

## Evidence and maintenance

The C17 OPM engine is specialized from the approved BSD-3 ymfm OPM source at
`81aec25ccbb98f4873a255f7551ac4dadac59b4a`; only its OPM implementation,
required FM/common implementation, declarations, and license are in scope.
The pinned implementation is used as an exact translation oracle, not as proof
of physical XM behavior. Keep the full BSD-3 notice and pin in
`THIRD-PARTY-NOTICES.md` and `PROVENANCE.md`. Chip numeric expectations come
from the Yamaha documentation before parity comparisons. Re-run the actual
receipt-bound oracle when changing the port or updating the pin; fixed vectors
in recurring C tests do not replace that update-duty run.

The executable translation corpus is shared by [`ym_vectors.h`](../../tests/audio/ym_vectors.h)
and the test harness. Each named case is at most 2,048 sample steps:

| Case | Steps per chip | Coverage |
|---|---:|---|
| `algorithms` | 2,048 | All eight OPM connection algorithms; both raw channels cross zero. |
| `operator_positions` | 1,024 | Key each of the four operator positions. |
| `key_envelope` | 1,024 | Attack and release continuation. |
| `feedback` | 1,024 | All eight feedback settings. |
| `noise` | 512 | Channel 7 noise output. |
| `lfo` | 512 | All four LFO waveforms with AM and PM sensitivity. |
| `panning` | 512 | Muted, left, right, and stereo routes. |
| `phase_wrap` | 2,048 | High-frequency phase wrap. |
| `repeated_writes` | 512 | Repeated total-level writes during sound generation. |
| `interleaved_two` | 512 | Two independent chips advanced and updated in alternating order. |

The fixed hashes use FNV-1a 64 over signed 16-bit output bits encoded low byte
then high byte, left then right, and chip order for the interleaved case. The
receipt-bound oracle compares every actual sample and reports the per-case
hashes; C-only `ym.synthesis` retains those verified expectations for regular
CI. `ym.controls` rejects a one-bit output change, swapped channels, a missing
case, and the wrong seed identity. These translation checks establish port
equivalence to the named seed workload only.

To repeat the update-duty comparison after changing the C port or prepared
pin, first build the normal C target, then run:

```sh
cmake -DROOT=. -DSEED=build/v6-ym-seed -DWORK=build/v6-ym-oracle -P tests/audio/ym_oracle.cmake
```

The command verifies each of the six approved input hashes and the prepared
object hash from `source-receipt.json` before linking. It uses the already-built
object and never fetches or recompiles the seed.
