## Control and containment contract

The NCI documentation does not promise loopback binding. Use the existing runner `/usr/bin/sandbox-exec` facility to deny external IP traffic before exec and allow only loopback UDP control/replies while retaining app OS services and file access. Permit the app's selected UDP bind only when the traffic restriction is demonstrably enforced. Do not install a firewall, require sudo, change runner-wide firewall settings, or fall back to an unrestricted socket. Generate the narrow profile under the owned output directory. Before any RetroArch launch, exercise that exact profile against an owned UDP helper: loopback request/reply succeeds and a request sourced from the runner's non-loopback interface cannot be delivered. Test IPv4/IPv6 or deny the unused family. Missing sandbox support, a profile failure, or a negative control that does not prove external rejection stops before launch.

Reserve an ephemeral port, reject preexisting owners, release it immediately before the single spawn, then prove exactly one socket owner is the child PID and resolved executable path. Use checked native process/socket information or `/usr/sbin/lsof` with exact PID/port predicates; prove the same child with waitpid. A race, stale PID, unrelated owner, or failed ownership query is fatal. Never send QUIT or a signal to an unproved PID/endpoint. After ownership is established, require VERSION 1.22.2 and GET_STATUS's paused/playing fixture basename plus independently computed fixture CRC. Verify the same-run core path/digest from the prepared command and actual host load log. A VERSION reply alone proves neither process nor content identity.

Use only documented NCI replies. `READ_CORE_MEMORY` reads the published system memory map; observe the fixture marker/counter at $2300. GET_CONFIG_PARAM supports directory queries, not arbitrary run-ahead settings. The actual save/load path saves at S, advances eight frames with exact committed progress observations, loads once, proves restored S and its independently judged picture after the fixture presentation phase, then replays the same interval and compares expected progress and whole pictures. Account for any presentation-refresh frame against the restored point and the 120-frame limit. Do not assume LOAD_STATE refreshes cached video.
