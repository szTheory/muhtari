## Scope treatment

Task 1 is the tracer: the rename runs through the generator, the self test and the published page in one slice, and the existing freshness test proves it. Task 2 corrects the three claims entries and adds the guard that would have caught the wrong one. Deviation from a locked decision, recorded: D-17 named this evidence kind with the word gameplay. That name rested on a misreading, not on missing data: D-17's premise took the title@ predicate as gameplay evidence, while docs/emulation-tests.md (title) already defined it as a frame hash, the screen a sample shows by frame F. The verification (gap 2) pointed out the misreading; it brought no new data. The kind keeps its rule and changes only its name, and Task 1 records that as a dated amendment beside the existing D-13 amendment. The sample guard in Task 2 enforces a contract the page already publishes, that each claim names the tests that exercise it (D-17; must_haves truth 2, with the guard itself as truth 3): without it the generator checks only that a named test exists, which is how a linear sample's test came to back the supergame claim, so the guard and its fault case are required by that contract rather than added as an improvement.
