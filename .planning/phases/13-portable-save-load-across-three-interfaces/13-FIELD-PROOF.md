# Phase 13 private state field proof

This ledger records the private visitor shipped by plan 13-01. It is evidence for the exact packed payload in 13-DESIGN.md, not a public save format or a portability claim. All offsets below are absolute offsets from that table; the table is authoritative for each leaf's byte offset, width, signedness, and row-major order. The visitor in src/state.c is the only serializer/validator/applicator and walks a fixed source-defined field sequence. Dynamic memory lengths come from the already-installed instance, never the payload.

## Cross-field relationships and controls

The visitor checks these decoded relationships before APPLY: lag_frames <= frames; frame_start <= frame_deadline; frame_start <= bus.ticks <= frame_deadline; cpu.poll_phi2 <= bus.phi2; bus.clock_origin_tick <= bus.ticks; bus.clock_origin_phi2 <= bus.phi2; maria.origin <= bus.ticks; synth.origin <= synth.horizon <= synth.tick; synth.phase < synth.sample_den; synth.sample_num/sample_den/max_samples exactly match installed timing; audio_rem < synth.sample_den; synth.pending_tick >= synth.tick when pending; and secondary is zero unless one POKEY is installed. Public validation adds operation-specific continuation relationships: bounded frame span and clock headroom; MARIA/synth clocks near the current frame; TIA next phase within 168 ticks; installed POKEY edge/cycle clocks near bus time; RIOT timer not in the future beyond its write-cycle convention; and active RDY/NMI/HALT/SaveKey deadlines within source-produced windows. Tests preserve private full-width representation controls and reject checksummed hostile public clock tuples before apply. Fixed topology and lengths are checked against the installed instance before the visit; checked pointer arithmetic and alias rejection cover the instance and its single combined ROM/RAM/expansion allocation.

All payload-controlled loops are fixed by compiled arrays or installed lengths: 313 MARIA rows, 2 ports and axes, 2 packet records, 16 synth impulses, 1103 PCM cells, 2 POKEYs x 4 channels, 64 SaveKey page bytes, and the validated installed C/E/B extents. Validation uses bounded scalar scratch and does not allocate or copy a full instance. APPLY first validates the entire payload, keeps the live battery generation as a host token, applies in place, restores size tags and derived port/MARIA/bus indexes, and increments battery generation once only when battery bytes differ. `core.state.battery` also checks equal/repeated/refused restores, unsigned token wrap, an accepted pending-page rollback through the existing commit path, stable independent spans, unchanged observer counters, and an untouched temporary host-file sentinel. The registered core.no_alloc_after_load case rejects allocation/free around SIZE/WRITE/VALIDATE/APPLY and compares the replayed next video/PCM and independent mailbox observation.

## Canonical values and excluded state

Canonical zero rules currently apply only to MARIA stats rows outside the selected region and inactive physical PCM FIFO cells. Every other serialized byte is retained at its fixed width, including raw registers and diagnostic counters. Input packet padding and public size tags are omitted; size tags are reconstructed. bus.next_deadline and ports.next_tick are derived and rebuilt. Effective region/profile/load device; cart board/info/ROM and wiring; expansion kind; battery attachment/firmware metadata and generation; machine loaded state; allocator/observers/audio work; BIOS/HSC firmware and staging; ROM; MARIA row/pitch pointers; all callbacks and pointers are excluded. The dynamic byte spans themselves are serialized in installed order, with addresses and lengths preserved.

## Effective machine identity cache

`src/state.c:muhtari__state_bind_identity` computes the private 32-byte digest with the existing owned SHA-256 implementation. It hashes the exact domain string `MUHTARI-STATE-IDENTITY` including its terminating NUL, then the 22 tagged, length-prefixed little-endian records specified in `13-DESIGN.md`. The ROM record reads the post-install normalized bytes in `m->cart.rom`, so A78 header/title/warnings and caller buffer addresses do not participate. The records bind the effective region, board/RAM wiring, POKEY addresses, IRQ mask, resolved expansion and load-time port owners, battery topology, boot mode and installed BIOS, HSC mode and installed firmware bytes, machine profile, and synth wiring. Port identities come from `muhtari__ports_device`, after `power_cycle` has resolved overrides and serial-device ownership.

The cache is written once at the end of a successful `muhtari_load`, after cart, battery and BIOS commits and final power-on, with no fallible work after it. A refused initial load leaves the zero-initialized cache empty; refused replacements preserve the old cache. `muhtari_power_cycle` does not change identity. Repeated state sizing, write, validation and apply use the cache without hashing or scanning immutable media and allocate nothing. The complete ROM read occurs only at successful content installation; the accepted maximum input is `MUHTARI_IMAGE_SIZE_MAX` (1,048,704 bytes, including an optional 128-byte header), with at most 1,048,576 installed ROM bytes in the digest record. Tests in `core.state.lifecycle` check failed-load retention, power-cycle stability, caller-buffer mutation, repeated queries and allocation counters. Tests in `core.state.topologies` compare independent instances and headered/raw equivalent content, Auto/explicit equivalent expansion and port choices, and distinct ROM, board, board options, RAM, region, audio wiring, IRQ, controller, expansion, SaveKey, BIOS, HSC mode/firmware, and profile choices.

The cache is instance metadata, not part of the packed payload. The payload still excludes immutable ROM/BIOS/HSC bytes, host pointers, source paths and mutable battery generation. API 8 compares this cached identity before validating and applying public state bytes; no cross-platform execution claim is made here.

## Scope boundary and remaining proof

The private tracer demonstrates a canonical fixed-width payload, field-domain rejection, bounded installed-size traversal, no-allocation restore, loaded generated-machine continuation and cached effective identity. Plan 13-03 adds the 64-byte envelope, CRC, public API and battery rollback/continuation checks. Public validation keeps the private format's full-width representation but accepts clock relationships only when the next frame and scheduler work remain bounded. Checksummed far-future HALT, stale TIA/synth and near-limit overflow tuples fail before machine mutation; generated-machine save/load/continuation and no-allocation checks pass. The source still has no global emulated-time cap. STATE-02 remains explicitly unclassified in the phase design; this ledger does not resolve it by inference. No Phase 12, hosted BE, RetroArch or real-ROM action was run.

## Independent continuation boundary (plan 13-04)

`core.state.topologies` seeds a valid two-entry PCM ring window in the source
and restores it into an independently loaded destination. The payload's
`synth.pcm_read` and `synth.pcm_count` define active FIFO cells during
validation; the destination's live cursor is not authoritative for candidate
classification. This is tested with source cursor 5/count 2 while the
destination begins with an empty ring. The earlier validator rejected this
valid state with `MUHTARI_STATUS_ERR_INVALID_STATE`; after classifying cells
from the candidate cursor/count, `topologies`, `fields` and `battery` pass.

The continuation matrix also checks the first and last bytes of installed cart
RAM, expansion RAM and battery spans; a raw TIA-to-mixer transition; independent
mailbox and electrical observations; and resumed PCM, frame/audio counters,
video, canonical bytes and span identity. MARIA's pending cursor continues
through normal frame execution. Separate bus-owner HALT/NMI deadlines exercise
those pending boundaries without claiming a mid-burst MARIA snapshot.
