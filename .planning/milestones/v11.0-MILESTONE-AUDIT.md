## End-to-end flows

1. **Inputs:** wide Windows arguments convert strictly to UTF-8; each filesystem operation converts paths back to
   UTF-16. Cartridge, movie, BIOS, HSC firmware and state inputs use the same supported-form checks.
2. **Alias safety:** every requested output is checked against all inputs and other outputs, including the derived
   battery path. Existing files use volume/file identity; absent targets use parent identity and namespace-aware
   leaf comparison. Unsupported overlaps fail before emulation or output mutation.
3. **Outputs and failures:** state, frame image, trace and battery writes use a temporary sibling and replace only
   after successful write, flush, sync and close. Failure controls check preservation and cleanup.
4. **Windows acceptance and release:** `runner.trace.paths` requires the real drive/UNC measurement matrix and
   share cleanup on both Windows architectures. Release CI runs on the exact release commit, then publication
   verifies assets and provenance before the latest-install check.

The integration review found no broken connection. There are no API routes or UI flows in this CLI/filesystem
milestone.
