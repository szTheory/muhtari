# Requirements: muhtari v4.0 — Browser/WebAssembly core readiness

**Defined:** 2026-11-10
**Core value:** 7800 games behave as on the console, identically across platforms,
from a small MIT-licensed C library hosts can embed.

The v3.0 closeout is an explicit override with nine unmet requirements preserved
in its archive. This milestone takes the owner-ranked browser/WebAssembly direction
through the existing libretro deliverable. It adds no browser player or device UI.

## v4.0 Requirements

### Recurring milestone tune-up

- [x] **TUNE-08**: Maintainers can use measured current evidence to select and ship one small pipeline, quality, or documentation improvement while preserving required checks; if no safe improvement is supported by evidence, they record the exact gap and a bounded disposition before feature work proceeds.

### Browser-targeted libretro core

- [x] **WASM-01**: A pinned Emscripten build produces a browser-consumable WebAssembly form of the existing libretro core, with the required loader/link contract and exported/imported surface documented.
- [x] **WASM-02**: An offline headless Node host can load the built core, run its libretro lifecycle with an owned fixture and scripted input, capture video/audio callbacks, and exercise state serialization without adding a browser UI or device code.
- [x] **WASM-03**: Deterministic frame, audio, input and save/restore observations from the WebAssembly core match independent native expectations, with representative refusal/fault controls and no ROM/BIOS bytes added to the repository.
- [x] **WASM-04**: Maintainers can reproduce and report WebAssembly artifact size and warmed headless throughput against the same-source native core without presenting those measurements as cross-browser or device performance claims.

## Deferred Requirements

The following requirements remain unchecked from v3.0 and are not part of this milestone: TUNE-06, TUNE-07, PLAY-01, PLAY-02, PLAY-03, PLAY-04, FRONT-02, FRONT-03 and FRONT-04. Their evidence and acceptance stops remain in `milestones/v3.0-phases/` and `milestones/v3.0-MILESTONE-AUDIT.md`.

Future work may add a real-browser host/player, browser keyboard/gamepad/audio behavior, browser persistence, phone power measurements, or paired Playstead acceptance only after a separate scoped decision.

## Out of Scope

- A browser page, player UI, window, audio device or input device in Muhtari.
- Changing the existing library, headless runner and libretro core deliverables into a multi-core frontend product.
- Claiming Chrome, Firefox or Safari acceptance, real-browser device behavior, Playstead integration, or user-device power/performance from a Node host.
- Adding ROM, BIOS or save bytes beyond fixtures already listed in `tests/roms/manifest.txt`.
- Reopening the v3.0 host permission request or renewing any Phase 12/14 host or remote allowance.
