still unpublished. The exact `v0.15.0` tag remains on the source whose Wasm32

## Main CI timing and efficiency review

Run 43720418561 took 45m25s from workflow creation to completion. The first job
started 2s after creation; the platform build jobs started within 10s. No job was
canceled. The title and performance jobs were skipped under their push-event
conditions. The longest lane was Windows ARM64 at 43m07s. Its independent-base
quality step ran 26m27s after the current-source build/test/package step had
passed. Windows x64 took 24m37s, including 16m52s for its independent-base
quality step. The dependent Wasm32 report-only lane then passed in 2m05s; the
required CI roll-up passed. GitHub emitted a generic macOS ARM64 queue-capacity
annotation, but the actual build job started 10s after workflow creation.

The Windows baseline is intentionally configured to run the prior-source CTest
inventory serially because the runner lacks CTest jobserver integration. This
single run confirms that baseline comparison is the dominant cost, but it does
not justify changing serial execution, test coverage, the 68-minute Windows job
cap, or pipeline structure. Compare another equivalent run before proposing
such a change.
