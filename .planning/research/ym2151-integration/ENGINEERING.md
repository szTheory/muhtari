# YM2151 integration engineering note

**Scope:** Source-grounded constraints for the selected YM2151 feature, to inform Phase 20 discussion/research. This is not an implementation plan or evidence of runtime performance.

## Recommendation

Port only the approved ymfm OPM path at pin 81aec25ccbb98f4873a255f7551ac4dadac59b4a into a fixed-width, C17 module whose mutable register, operator, timer, busy, clock-phase, and output state is owned by each Muhtari instance. Drive it from the selected absolute MARIA-tick cadence and let the existing bus/cart and synthesis owners handle register access, IRQ sampling, and mono PCM. Keep current no-YM results and state representation byte-identical. For YM topology, combine the signed stereo chip outputs through a documented integer gain/rounding rule, then prove the resulting signed/unsigned mixer, kernel, DC-blocker, clipping, and visitor bounds. The existing source does not establish a calibrated board gain, so this is a deterministic digital profile choice, not a hardware loudness claim. ## Bounded work and event density

The pinned OPM model declares “OUTPUTS = 2”, “CHANNELS = 8”, “OPERATORS = CHANNELS * 4”, and “DEFAULT_PRESCALE = 2”; its generate loop advances the engine once and emits both outputs per generated sample. At that prescale the YM output step is every 64 chip clocks, or every 128 MARIA ticks under the selected profile. [VERIFIED: upstream ymfm_opm.h@81aec25:111-124] [VERIFIED: upstream ymfm_opm.cpp@81aec25:523-536] [VERIFIED: .planning/preparation/A7800-AUDIO.md:139-144]

The current source quotes the NTSC timing tuple as “{263u, 242u, 119402u, 117174u, 88u, 13125u, 801u}” and the PAL tuple as “{313u, 292u, 142102u, 139874u, 4000u, 591149u, 962u}”. Its overshoot inputs are quoted as “#define MUHTARI__SYNTH_RDY_TICKS 456u”, “#define MUHTARI__SYNTH_DMA_TICKS (2u * 454u)”, “#define MUHTARI__SYNTH_HOLD_ROUND_TICKS 12u”, “#define MUHTARI__SYNTH_ACCESS_TICKS 6u”, “#define MUHTARI__SYNTH_OPCODE_CYCLES 8u”, and “#define MUHTARI__SYNTH_INTERRUPT_CYCLES 7u”; their formula yields 20,730 ticks. A frame-deadline-only arithmetic ceiling is 933 NTSC or 1,111 PAL YM output steps. To cover the actual frame run including the established CPU/interrupt overshoot, use a provisional ceiling of ceil((frame_ticks + 20,730) / 128): 1,095 NTSC and 1,273 PAL output steps. These are structural scheduling ceilings, not measured performance, and the implementation must preserve the existing rational phase/carry semantics rather than resetting phase at frame boundaries. [VERIFIED: src/internal.h:29-58] [VERIFIED: src/frame.c:71-105]

At each generated sample, the engine calls one clock over the eight channels; each channel has four operator slots. This is a bounded fixed-count inner workload, with a prepare sweep over at most eight channels after register modification and periodically after 4,096 generated samples. Timer A's shortest period is one generated sample; timer B's shortest is 16. Over one maximum PAL frame execution window, the structural limit is 1,273 output steps and 10,184 channel-clock calls. A single shortest-period timer A can therefore expire at most 1,273 times in that window. These are source-derived operation ceilings, not benchmarks. [VERIFIED: upstream ymfm_fm.ipp@81aec25:1280-1320] [VERIFIED: upstream ymfm_fm.ipp@81aec25:1473-1495]

The bus source states “A fast cycle is 4 ticks with its data at the phi2 fall, tick 4”. A deliberately loose bus-only ceiling is therefore floor(119,402/4) = 29,850 CPU write accesses in a logical NTSC frame, or at most 32 write accesses per 128-tick YM output interval; address-plus-data pairs consume two such accesses. Actual instruction streams necessarily spend accesses on reads too, so this is an adversarial upper bound, not an expected game workload. Stress repeated data writes without re-addressing, alternating address/data writes, status reads around busy/timer transitions, and accesses landing on a YM sample/timer deadline. [VERIFIED: src/bus.c:16-21] [VERIFIED: src/internal.h:35]

## Mixer and observer constraints

The existing mixer computes a nonnegative current from TIA/POKEY, normalizes it to MUHTARI__SYNTH_MAX_LEVEL, and stores the exact “uint16_t raw[10];” source array. The observer stores the exact “uint8_t raw[10];” cache and “uint8_t source, level;” pending/carry records, although the callback and runner hash accept uint16. Thus preserving the callback type alone is insufficient: the observation cache must retain the signed YM sample bit pattern, and source enumeration/loops must admit two YM output channels. Keep source order and all old-source records identical on no-YM machines. [VERIFIED: src/internal.h:65-78] [VERIFIED: src/synth.c:263-280] [VERIFIED: src/internal.h:419-424] [VERIFIED: runner/main.c:1493-1503]

Do not treat signed YM samples as another unsigned “level” in the existing positive mixer formula. Choose an integer attenuation/midpoint or an equivalent bipolar-current representation, with explicitly defined rounding and conversion of signed sample bits. Re-derive the possible mixed level and delta, signed impulse additions, Q23 integrator and Q30 DC-blocker limits, pre-clip peak, and clip counters for YM topology. Conditional gain only when YM is installed is the least disruptive fit: it can keep every no-YM sample and state value unchanged and may fit the existing global range, but the range must be demonstrated before retaining it. Do not widen global visitor limits or claim spare PCM headroom by inspection. No source qualifies an analog YM-to-POKEY gain. [VERIFIED: src/synth.c:228-260] [VERIFIED: src/internal.h:43-78] [VERIFIED: .planning/research/ym2151-profile/EVIDENCE.md:54-58] [VERIFIED: .planning/research/ym2151-state/POLICY.md:31-36]

Same-tick observation currently documents “At most ten source changes per master tick, including both half-edge subevents and a CPU write” and retains an overshoot carry sized from that assumption. YM adds up to two channel transitions on a generated output edge, potentially coincident with TIA/POKEY or a CPU write. Recompute pending and carry bounds from the existing overshoot plus the number of YM edges in it; do not simply keep the old ten-per-tick proof or multiply it by an unexamined factor. [VERIFIED: src/synth.c:263-280] [VERIFIED: src/synth.c:304-345] [VERIFIED: src/internal.h:39-59]

## State and refusal semantics

Current state constants are exactly “#define STATE_FORMAT 1u” and “#define STATE_BEHAVIOUR_REVISION 6u”. The accepted recommendation is “Keep API 8 and ABI 1”; “Preserve all old non-YM PCM/transition results and native snapshot representation”; and “Use a distinct format 2 / behavior 7 envelope only for YM machines”. Treat these as the compatibility target for later phase decisions, not as already implemented or tested facts. [VERIFIED: src/state.c:11-16] [VERIFIED: .planning/research/ym2151-state/POLICY.md:42-57]

The visitor currently serializes exactly ten synth raw values. Add YM fields and identity only on the YM topology; do not unconditionally widen that loop, because it changes existing non-YM state extents. Validate full envelope, destination topology/identity, YM register ranges, timer state, and mixer ranges before applying anything. Preserve battery and live-machine no-mutation on invalid state or unsupported load. For non-YM state compatibility, use a producer built from the actual kickoff revision and test it against the new consumer; a state synthesized by the new writer is not an independent legacy fixture. [VERIFIED: src/state.c:903-907] [VERIFIED: src/state.c:1274-1325] [VERIFIED: .planning/research/ym2151-state/POLICY.md:23-40] [VERIFIED: .planning/research/ym2151-state/POLICY.md:76-85]

When busy-timer writes, high-rate register traffic, reset, and state load coincide, ensure deadlines are updated monotonically and repeated timer overflows are processed in bounded time. Restore must invalidate any derived waveform/envelope caches just as the seed does, while serializing all mutable state that affects future output. The source has fixed-size 8-channel/32-operator storage; keep tables immutable/shared and all mutable counters per instance. ## Independent numeric expectations versus port parity

Use the Yamaha datasheet/application manual for chip expectations, independent of ymfm: the timer periods are 64 × (1024 − timer-A value) YM clocks and 1,024 × (256 − timer-B value) YM clocks. At the selected output cadence those equal (1024 − A) and 16 × (256 − B) generated output steps. Useful edge expectations are A=1023 → 64 chip clocks / one output step and B=255 → 1,024 chip clocks / 16 output steps. Yamaha describes the timer IRQ pin as active-low/open-drain; the chosen A78 profile converts this to the existing active-high bus request only for a valid v4 IRQ-mask bit 2. Sources: [Yamaha YM2151 datasheet](https://bitsavers.org/components/yamaha/YM2151_199112.pdf), [Yamaha YM2151 application manual](https://map.grauw.nl/resources/sound/yamaha_ym2151_synthesis.pdf), [A78 Header Specification revision 1120](https://7800.8bitdev.org/index.php?title=A78_Header_Specification&oldid=1120), [VERIFIED: .planning/research/ym2151-profile/EVIDENCE.md:46-52]

Keep a separate seed-parity corpus against the exact pinned OPM source: address/data register traces; both signed channel outputs at each generated step; status busy and timer flags; callback/deadline transitions; reset/isolation; and continuation after save/restore. The seed says offset-0 data reads return 0xff, offset-1 reads status, writes to register 0x1b also report the upper two bits through an external callback, and a data write sets busy for 32 × prescale clocks (64 at default prescale). Those latter details are seed-parity expectations, not independent XM wiring claims. Do not claim seed agreement proves the physical board's gate, clock, IRQ wiring, or analog gain. ## C17 hazards and adversarial review points

Do not mechanically translate C++ integer helpers. The source contains signed right shifts and a signed left shift in its DAC quantization path; in C, negative right shift is implementation-defined and left-shifting negative or overflowing signed values is undefined. Audit all signed shifts, products, additions and narrowing conversions; use unsigned bit operations or explicitly widened, bounded arithmetic, while preserving every DAC quantization bit for parity. Also guard bit masks and leading-zero helpers against zero and width-sized shifts. [VERIFIED: upstream ymfm.h@81aec25:181-203,227-249]

For adversarial traffic, interleave writes at every minimum bus cycle with reads of status at exact busy end and timer overflow boundaries, plus enable/disable latch writes and a timer reload on the same tick. For integer safety, exercise both output polarities at −32768 and 32767, largest operator sums, phase wrap, timer reload, noise/LFO state, and mix transitions at the derived limits. For state safety, truncate/flip YM payload values and identities, restore into a different topology, and confirm rejection leaves machine and battery state unchanged. These checks target concrete overflow, event-ordering, and transactional-restore risks found in the current interfaces. [VERIFIED: upstream ymfm_opm.cpp@81aec25:482-496] [VERIFIED: src/bus.c:277-306] [VERIFIED: src/state.c:1303-1325] [VERIFIED: .planning/research/ym2151-state/POLICY.md:76-85]
